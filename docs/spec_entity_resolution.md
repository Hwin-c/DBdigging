## 1. 개요 및 문제 정의

**<디비디깅(DBDIGGING)>**의 2-Mode 이부 네트워크(Bipartite Network)는 노래 노드 집합($V_{\text{song}}$)과 인물·그룹 노드 집합($V_{\text{person}}$)으로 구성됩니다. 멜론(Melon) 원본 메타데이터 수집 시 아티스트 고유 숫자 ID가 부여된 경우도 존재하지만, 작사·작곡·편곡 크레딧이나 구보 가창/피처링 표기에서 **고유 아티스트 ID 없이 텍스트 이름만 존재하는 경우** 데이터 파이프라인에서 이를 유실하지 않기 위해 **가상 ID(Virtual ID)**를 발급했습니다.

이로 인해 엔티티 식별(Entity Resolution) 관점에서 서로 반대 방향인 **2가지 구조적 위험**이 공존합니다.

1. **위험 A — 동명이인 병합 (False Merge / Homonym Collapse):**
   - 실제로는 서로 다른 동명이인 창작자/가창자가 고유 숫자 ID 없이 동일한 텍스트 이름(예: `name_이동화`, `name_이성은`)으로 기재된 경우, 하나의 가상 ID 노드로 합쳐져 **실제로는 무관한 시대·장르의 두 곡 사이에 거짓 지름길(False Shortcut)을 형성**할 위험.
2. **위험 B — 동일인 분리 (False Split / Split Identity):**
   - 실제로는 동일 인물·그룹임에도 어떤 곡에서는 정식 멜론 숫자 ID(예: `1` 나훈아, `751` 김창완)로, 다른 곡에서는 가상 ID(예: `singer_나훈아`, `name_김창완`, `artist_김창완`)로 분리 수록되어 **UI 카드 중복 노출 또는 탐색 경로 단절**을 유발할 위험.

> Phase 13에서 도입한 `engine.getSafeMergedPersonIds()`는 UI 카드 조회(`getConnectedPersons`, `getConnectedSongs`) 시 정식 ID와 동일 이름 가상 ID를 병합해 주지만, **`GraphStore.adj` (BFS 최단 경로 탐색용 인접 리스트)에는 두 노드가 별개 노드로 분리**되어 있어 BFS와 실제 플레이어 클릭 가능 경로 사이에 미세한 괴리가 존재합니다.

## 4. 위험 완화 규칙 후보 설계 및 4대 지표 실측 비교

동명이인 병합 위험을 줄이면서 네트워크 연결성을 보존하기 위해 아래 후보들을 실제 번들에 적용하여 4대 지표를 실측했습니다.

- **Baseline (현재):** `store.adj`의 모든 가상 ID 노드를 제한 없이 허용.
- **후보 1A (`name_*` 미등록 창작자 가상 ID 전면 제외):** 동명이인 위험이 가장 높은 `name_*` (5,745개) 노드를 경로 탐색에서 제외하되, 그룹/가창 연결에 필수적인 `singer_`, `feat_`, `group_`, `artist_`는 유지.
- **후보 1B (모든 가상 ID 19,859개 전면 제외):** 비숫자 ID 전체를 경로 탐색에서 완전히 배제.
- **후보 2 (가상 ID 페널티 가중치 부여 — 정식 ID 우선 경유):** 모든 가상 ID의 연결성은 유지하되, 최단 경로 및 힌트 BFS에서 가상 ID 경유 시 가중치 페널티($+1$턴 상당 비용)를 부과하여 **정식 멜론 숫자 ID 경로가 존재할 경우 항상 정식 ID를 우선 채택**.
- **후보 3 (`name_*` 활동 연도·장르 클러스터 분리):** `name_*` 가상 ID 중 참여곡 간 연도 공백이 10년을 초과하거나 연도 차이 5년 이상이면서 장르가 불일치하는 노드(185개)를 감지하여 별도의 시대·장르 서브노드(401개)로 분할하고, 비인물 노드(`name_미상`, `name_작자미상`, `611339` 작자미상)의 허브 왜곡을 격리.

## 5. 엔지니어링 권장안 (최종 결정은 사용자 승인에 따름)

실측 데이터를 종합할 때, 단순 전면 제외(후보 1A/1B)는 1,927~3,683곡의 연결성을 상실시키고 데일리 시드(`singer_FIFTY FIFTY`, `group_SHINee` 등)를 파손시키는 반면, **아래의 복합 방안(후보 2 + 후보 3 핵심 결합 + `artist_` 누락 패치)** 이 커버리지 손실 없이 데이터 무결성을 극대화합니다.

1. **[즉시 패치 권장] `isVirtualPersonId` 및 `getSafeMergedPersonIds`에 `artist_` 접두사 추가:**
   - 번들에 실제 존재하는 5번째 가상 ID 접두사 `artist_` (2,850개)를 안전 병합 대상에 포함시켜 `김창완`, `김현호` 등의 누락을 해소합니다.
2. **[비인물 허브 차단 권장] `미상` / `작자미상` 블랙리스트 격리:**
   - 실제 인물이 아닌 메타데이터 결측치 노드(`name_미상`, `name_작자미상`, 정식 ID `611339` 작자미상 — 합계 1,004곡 연결)는 크레딧 징검다리로 사용할 수 없도록 경로 탐색 및 카드 목록에서 제외합니다.
3. **[동명이인 완화 권장 — 후보 2/3 선택]:**
   - **런타임(웹 앱) 적용 시:** 정적 번들 수정 없이 즉시 적용 가능한 **후보 2 (가상 ID 페널티 가중치)** 또는 **후보 3 (`name_*` 연도·장르 클러스터 분리)** 를 로더 초기화 시점에 적용하면, 메인 대륙 커버리지(96.30%~96.34%)와 데일리 시드 100개 유효성(100/100)을 온전히 지키면서 비정상적인 시대 초월 동명이인 점프를 차단할 수 있습니다.
